# Northflank Developer Sandbox deployment

This is the existing paper-only bot with a Dockerfile and an IST weekday scheduler. The underlying strategy is unchanged. No daily login, SSH, systemd, or public port. One replica only. Local tests are mocked; Docker build, Kotak connectivity and Northflank deployment have not been tested here.

1. Create a private GitHub repository (e.g. neo-paper-bot). Upload the CONTENTS of this extracted directory, including the Dockerfile, requirements.txt, bot.py, alerts.py, northflank_runner.py, config.json, calendar.json and .dockerignore at the repository root. Do not upload real .env, API tokens or runtime files.
2. Create a Developer Sandbox project in https://app.northflank.com/ using Northflank managed cloud; choose the nearest offered region. Remain on the free plan.
3. Link GitHub, then Create New > Service > Combined. Choose the repository/main, Dockerfile build, Dockerfile /Dockerfile and build context /. Use the smallest free compute plan available (prefer 512 MB or more), one instance, no public or private ports, no HTTP health checks, no command override.
4. Under runtime variables (not build arguments), set NEO_CONSUMER_KEY to your own Kotak token. Optional: TELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID. No MPIN or TOTP.
5. Attach a single read/write volume at EXACT path /app/runtime (not /app). Use the smallest allowed size if the dashboard confirms it is covered by your plan. The container runs as UID/GID 10001; the mounted directory must be writable by that user. If a free volume isn't available, set ALLOW_EPHEMERAL_PAPER=1 ONLY for short tests. This loses simulated positions and history if the container is replaced and invalidates continuous paper results. Do not enable paid resources unintentionally. The default refuses to run without a volume.
6. Deploy; open logs. Run `python -u bot.py --mode paper --preflight` in the service container terminal during market hours, preferably before the scheduled session (the engine locks runtime/paper while active). If it reports an instance lock, do not run a second bot; test outside the session or on a separate temporary test service. Check both indices and spot quotes. Spot warnings need investigation.
7. Scheduler launches at 08:55 IST Monday-Friday (or at service startup within the session), starts no fresh entries after the strategy window, and waits after the engine finishes. A crash is retried during the session; after-hours interrupted positions may only recover at the next session. Calendar covers through Dec 31, 2026; replace with verified exchange holidays before 2027.
8. Trade history: /app/runtime/paper/trades.csv. In service terminal use `cat /app/runtime/paper/trades.csv`. Use Northflank CLI file transfer to export/backup files. Do not redeploy mid-session; turn off automatic deployment if possible. Telegram is optional but useful for daily gross P&L. P&L excludes fees and real execution effects.

To disable the next entry or request a simulated exit: `touch /app/runtime/paper/KILL` in the running service terminal (create the directory first if needed). Verify logs. Remove it only when ready. This is a paper simulation, not a live broker kill switch.
